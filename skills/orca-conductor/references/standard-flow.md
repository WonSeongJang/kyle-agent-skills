# 표준 흐름 패턴 (섹션 분해 → 배분 → 섹션 검수 → 보고)

섹션 단위 대량 작업용 패턴. 실행 절차는 `mechanics.md`, 왕복·검수 규칙은 `tiki-taka.md`, 엔진 선택은 `roster.md`를 따른다.

## 1) 분해 — 섹션과 등급

- 작업을 섹션(M1, M2, …)으로 나눈다 (M은 Milestone 라벨일 뿐, 기능적 의미 없음).
- 각 태스크에 난이도(low/medium/high)와 절차 무게(LIGHT/HEAVY)를 붙인다 — 판정 기준·래칫은 `tiki-taka.md`, 엔진·폴백은 `roster.md`. 무검수 단독 편성은 없다.
- 방향이 갈리는 태스크는 `tiki-taka.md`의 **배틀 오프닝**으로 시작한다 (구 §2 배틀은 그쪽으로 이사, 2026-07-21).
- 섹션 하나가 끝날 때마다 섹션 최종 검수(`gjc-codexpro`, 가재)를 한 번 배분한다.

## 2) 섹션 검수 — gajae

- 섹션의 일꾼 카드가 모두 completed면 gajae 터미널에 검수 카드를 배분한다.
- gajae 프롬프트 계약(항상 포함): "너는 검수 전용이다. 어떤 파일도 수정하지 마라. 심각도(치명/중요/사소)별 발견 목록과 근거 파일:줄만 보고하라. 일꾼들의 보고·기존 로그·증거를 불신하고 직접 실행·실측으로 검증하라."
- 검수 발견은 지휘자가 종합해 수정 카드로 만들어 일꾼에게 재배분한다. gajae가 직접 고치게 하지 않는다.

## 3) 보고

각 섹션 종료 시 kyle에게: 완료 카드 수, 배틀 결과, 검수 발견(심각도별), 남은 섹션, 사용량 상태를 쉬운 말로 보고한다. 병합·정리는 결정 관문 승인 후 실행한다.
