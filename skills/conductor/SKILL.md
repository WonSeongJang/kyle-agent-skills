# Why

지휘에는 축이 둘인데 지금까지 한 덩어리로 묶여 있었다.

```
축 A — 호스트          Orca / Rottie
                      터미널·워크트리·장부가 사는 곳

축 B — 에이전트 실행기   codex / omo / claude
                      작업자를 실제로 띄우는 CLI
```

**축 B는 호스트가 무엇이든 똑같다.** 그런데 `orca-conductor` 안에 두면 Orca 전용처럼 보이고, Rottie 쪽에서 같은 내용을 다시 적게 된다. 같은 내용이 두 곳에 있으면 갈라진다.

`orca-conductor` 라는 이름은 그 두 축을 한 덩어리로 묶은 결과다. 이 스킬은 **호스트와 무관한 것부터 하나씩 여기로 옮기는 자리**다. 대개편을 한 번에 하지 않고, 새로 만드는 것부터 여기 둔다.

# 지금 여기 있는 것

| 파일 | 무엇 | 누가 읽나 |
|---|---|---|
| `references/agent-runners.json` | 실행기별 실행법·필수 플래그·검증법·특이사항(날짜·근거 포함) | 감독이 작업자를 띄우기 전, 슈퍼가 편성을 정할 때 |

# 쓰는 법

- **모델 편성은 여기서 정하지 않는다.** 그건 `orca-conductor/references/routing-providers.json` 몫이다. 이 파일은 **"어떻게 실행하는가"**만 정한다.
- **실행기를 처음 쓰기 전에 `agent-runners.json` 의 해당 항목을 읽는다.** 특히 `required_flags` 와 `verify`.
- **새로 알게 된 것은 여기에 추가한다.** `measured`(실측 날짜)와 `evidence`(무엇을 보고 그렇게 판단했는지)를 반드시 함께 적는다. 근거 없는 항목은 넣지 않는다.

# 관통 규칙 — 실행기는 저마다 라우터 위에 얹힌 두 번째 결정자를 갖고 있다

2026-08-10 하루에만 두 가지가 나왔다.

```
codex   "모델 지정하지 마라" 를 대화에 직접 주입한다 (바이너리 안의 문자열)
omo     지정한 모델을 추천 목록 1순위(kimi-k3)로 조용히 갈아탄다 (TUI 에서만)
```

**둘 다 라우터가 정한 것을 실행기가 뒤집는다.** 그래서 실행기마다 **"지정한 대로 도는지 확인하는 법"**을 반드시 적는다.

그리고 **모델 자칭은 증거가 아니다.** 같은 실행에서 모델은 자기를 `openai/gpt-5.6-senpi` 라고 했지만 도구 기록은 `openai-codex / gpt-5.6-sol` 이었다. **도구가 기록한 값만 쓴다.**

# 공통 주의 — 긴 지시는 파일로 준다

호스트의 `terminal send` 는 여러 줄 텍스트를 **줄마다 Enter 로 제출**한다. 긴 카드를 통째로 밀어넣으면 여러 개의 별도 메시지가 된다(실측: 1121자 카드가 `five tasks` 로 인식됨).

**긴 지시는 파일에 쓰고 터미널에는 한 줄로 경로만 준다.** 실행기와 무관하게 안전하다.

# 앞으로 여기로 옮길 것

호스트와 무관한 지휘 규칙들 — 티키타카 사다리, 검수 계단, 카드 설계 원칙, 증거 규칙. 한 번에 옮기지 않는다. **판이 도는 중에는 옮기지 않고, 판 경계에서 하나씩 옮긴다.**
