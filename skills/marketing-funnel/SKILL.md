# Marketing Funnel — 팔리는 설계 워크플로우 라우터

## Why

- 누가: 제품은 만들 줄 아는데 "팔리게 만드는 절차"가 없던 1인 제작자([kyle])가
- 무엇이 불편한지: 만들고 나서 "홍보는 어떡하지?"가 되면 이미 늦는다. 강의 원문: "AI로 만든 다음에 홍보 어떡하지? 는 일단 안 된다."
- 우리가 무엇을 더 쉽게 해결하는지: 코드 한 줄 치기 전에 "결제 상태부터 역산한 퍼널 설계 -> 소액 수요 검증 -> 명단 수집 -> 문구" 순서를 강제한다.

> 근거: 2026-07-25/26 주말 강의 2개 필기 + 웹 리서치 4종.
> 심화 근거 문서가 필요하면 `references/research-map.md`를 읽는다.

## 절대 규칙 (항상 적용)

1. 설계 없는 광고 금지: WF-1 퍼널 설계 없이 광고 집행/랜딩 제작부터 시작하지 않는다. 광고는 증폭기일 뿐이다.
2. 만들기 전에 판다: 며칠 이상 걸리는 제작이면 WF-2 페이크 테스트로 수요부터 확인한다.
3. 순서는 직렬: WF-1 -> WF-2 -> WF-3 이 기본 축이다. WF-4는 WF-2/3 안에 포함되는 하위 절차다. 병렬은 리서치 팬아웃, 광고 안 A/B, 타깃 수집처럼 파이프라인 "밖"의 일회성 작업에만 쓴다. 병렬 실행이 필요하면 teammode나 orca-conductor를 호출 측에서 얹는다. 이 스킬이 지휘를 시작하지는 않는다.
4. 돈/법 안전선:
   - 광고 예산은 회당 1~2만원 단위부터. 총액 5만원을 넘기는 집행은 kyle 승인 후에만.
   - 콜드 문자/이메일 발송은 정보통신망법상 사전 동의가 필요하다. 무단 발송 계획이 나오면 멈추고 법적 대안(방문, 인스타 DM, 카카오 채널 개설 문의 등)을 먼저 제시한다.
   - 실제 결제 버튼 공개, 실제 청구는 kyle 승인 전 금지.
5. 안 날놓은 건 똥이다: 어떤 산출물이든 2주 이상 미공개 상태가 이어지면 WF-2로 강제 진입시킨다. "완벽주의"는 부끄러움의 포장으로 취급한다.

## 진입 판단 — 지금 어느 단계인가

아래를 보고 하나만 고른 뒤, 선택 카드를 출력하고 해당 reference를 읽는다.

| 상태 | 갈 곳 |
|---|---|
| 아이디어만 있거나, 기획 초기 | WF-1 (`references/wf1-funnel-design.md`) |
| 설계는 나왔고, 제작 전 수요가 궁금 | WF-2 (`references/wf2-fake-door-test.md`) |
| 수요 확인됨 / 출시 전 명단 모으기 | WF-3 (`references/wf3-leadmagnet-waitlist.md`) |
| 랜딩/광고/글/이메일의 첫 문구가 필요 | WF-4 (`references/wf4-first-line-hook.md`) |
| 여러 단계가 섞여 애매 | 가장 이른 단계부터 (아이디어 -> WF-1) |

선택 카드 형식:

```text

이번 산출물: <1페이지 퍼널 설계도 등>
```

## 워크플로우 요약 (상세는 각 reference)

- WF-1 퍼널 역산 설계: "결제하는 감정 상태"부터 거꾸로 올라와 경험 -> 신청 페이지 -> 이탈 방지 -> 유입까지 1페이지 설계도.
- WF-2 페이크 도어 검증: 랜딩 1장 + 만원 단위 광고 A/B. 전환율 숫자로 Go/Pivot/Drop 판정.
- WF-3 리드마그넷->웨이트리스트->출시: 미끼 상품 1개 + 입력 칸 1개 수집 장치 + 출시일 첫 판매.
- WF-4 첫 문구/후킹: soft/hard 판단 -> 공식 3안 -> Sugarman 검사 -> 실전 투입 후 숫자로 검증.

## 운영 규칙 (강의에서 굳힌 것)

1. 소비한 만큼 생산: 콘텐츠를 본 시간만큼 결과물을 세상에 남긴다.
2. 확률 싸움: 전환율은 천재적 문구 한 방이 아니라 단계별 확률을 조금씩 올리는 반복에서 나온다.
3. 귀찮음보다 도파민: 고객이 행동하려면 "얻는 기쁨"이 "입력의 귀찮음"을 넘어야 한다. 모든 신청/가입 단계에서 이 비교를 한다.
4. 고객 행동을 못 끌어내는 결과물은 컴퓨터에서 썩는다. 완료의 기준은 "만들었다"가 아니라 "행동 숫자가 찍혔다"다.
