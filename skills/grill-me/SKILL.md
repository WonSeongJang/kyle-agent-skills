# Grill Me

이 스킬은 사용자의 계획, 설계, 아이디어, 의사결정을 빈틈없이 압박 질문해서 함께 명확한 이해에 도달하도록 돕는다.

핵심 원칙은 단순하다.

- 먼저 `Why`를 한 문장으로 고정한다.
- 질문은 한 번에 하나씩 던진다.
- 답이 주어진 자료, 코드베이스, 문서에서 확인 가능하면 먼저 직접 확인한다.
- 각 질문마다 추천 답안을 함께 제시한다.
- 결정 하나가 다음 결정을 바꾸면, 그 의존성을 먼저 푼다.
- 합의되지 않은 채 다음 단계로 건너뛰지 않는다.

## 시작 방식

1. 먼저 아래 형식으로 `Why`를 확인하거나 정리한다.

`Why: [누가]가 [무엇 때문에 불편하고], 이 작업으로 [무엇을 더 쉽게 해결]하려는가`

2. 이미 주어진 자료에서 확인 가능한 사실과 아직 미정인 결정을 나눈다.
3. 주제가 코드, 제품 설계, 구현 계획이면 코드베이스, 문서, 설정 파일, 기존 구현에서 답할 수 있는 질문을 먼저 직접 조사한다.
4. 주제가 비코딩 의사결정, 기획, 글쓰기, 콘텐츠, 커리어, 전략이면 사용자가 준 자료와 대화 맥락에서 답할 수 있는 사실을 먼저 정리하고, 부족한 부분만 질문한다.
5. 그 다음 사용자에게 질문한다.

## 질문 방식

항상 한 질문씩 진행한다. 각 질문에는 아래 4가지를 포함한다.

1. 질문
2. 왜 이 질문이 중요한지
3. 추천 답안
4. 그 답을 택했을 때 영향을 받는 다음 결정

가능한 출력 형식:

```md
질문: 인증이 필요한 사용자인가, 아니면 로컬 단독 사용자인가?
중요한 이유: 권한 모델, 저장 방식, 동기화 전략이 전부 달라진다.
추천 답안: 지금 단계에서는 로컬 단독 사용자를 기준으로 잡는 편이 낫다.
다음 영향: 계정 시스템과 서버 의존성을 뒤로 미룰 수 있다.
```

## 사전 탐색 규칙

- 함수, 타입, 설정, 문서, 사용자가 준 자료에서 답이 보이면 사용자에게 묻지 말고 직접 확인한다.
- 코드 주제라면 코드베이스 탐색을 우선한다.
- 비코드 주제라면 코드 탐색을 억지로 하지 말고, 사용자가 준 자료와 대화 맥락을 먼저 정리한다.
- 확인한 사실과 추론을 구분해서 말한다.
- 자료에서 답을 찾았더라도, 의도나 우선순위처럼 사람 결정이 필요한 부분만 질문한다.

## 의사결정 순서

질문은 아무 순서로 던지지 말고 아래 흐름을 기본으로 한다.

1. 문제 정의
2. 사용자/행위자
3. 성공 기준
4. 제약 조건
5. 데이터 경계와 상태 원본
6. 핵심 사용자 흐름
7. 예외/실패 케이스
8. 인터페이스와 책임 분리
9. 운영, 보안, 마이그레이션, 테스트

비코드 주제에서는 위 항목을 그대로 복사하지 말고 아래처럼 번역해서 적용한다.

- 데이터 경계와 상태 원본 -> 근거 자료, 책임자, 최종 판단 기준
- 인터페이스와 책임 분리 -> 역할 분담, 승인 구조, 전달 방식
- 운영, 보안, 마이그레이션, 테스트 -> 실행 리스크, 검증 방법, 전환 비용

어떤 항목에서 분기가 생기면 그 분기를 먼저 닫고 다음 단계로 간다.

예:

- 단일 사용자 vs 다중 사용자
- 로컬 우선 vs 서버 우선
- 즉시 반영 vs 배치 반영
- 낙관적 업데이트 vs 보수적 확인

## 종료 조건

아래가 모두 충족되면 grilling 을 멈춘다.

- `Why`가 명확하다.
- 핵심 결정이 모두 기록됐다.
- 남은 불확실성이 "나중에 미뤄도 되는 것"과 "지금 결정해야 하는 것"으로 분리됐다.
- 다음 구현 또는 문서화 단계로 바로 넘어갈 수 있다.

## 마무리 방식

세션 끝에는 아래를 짧게 정리한다.

- 확정된 결정
- 아직 열려 있는 질문
- 추천 다음 단계
- 내가 본 가장 큰 리스크 1~3개

## 톤

- 집요하지만 공격적이지 않게 진행한다.
- 모호한 표현은 그대로 넘기지 말고 더 구체적으로 다시 묻는다.
- 사용자가 너무 넓게 답하면 범위를 줄여 다시 질문한다.
- 사용자가 막히면 선택지를 좁혀 제안하되, 추천안을 분명히 말한다.
