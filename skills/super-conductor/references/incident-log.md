- 후속(제품·스크립트): (a) companion kicker에 장부 대조 NUDGE 추가 — ready 카드 present + active dispatch absent + coordinator idle이면 감독 깨움(결정적 대조라 스크립트 허용 범위). (b) Orca 포크에 ready 카드 워치독(미발령 N분 → coordinator wake 이벤트) 기능 카드.

## 2026-08-04 — 임명장이 표준 판 세팅 절차를 덮어 중계기 미편성 (정체 2회의 공통 배경)

- 사고: upstream-sync-1 판 개설 때 슈퍼감독 임명장의 "첫 행동 4단계"(run-use·스킬 숙지·개시 선언·companion)가 사실상 체크리스트로 작동해, orca-conductor mechanics.md의 "중계기 편성은 예외 없이 항상 — 판 세팅 표준 절차"(kyle 2026-07-23 확정)가 이행되지 않았다. 감독은 mechanics를 숙지하고도 임명장 목록을 우선했다. 중계기 부재로 발령 누락 정체 2회를 모두 kyle이 육안 발견("스피너 안 도네", "또 멈춰있네").

- 박제: 슈퍼감독 임명장의 판 개설 첫 행동 표준은 고정 6단계다 — (1) run-use 바인딩 (2) 지휘 스킬 숙지 (3) companion 기동 (4) **중계기(relay) 스폰 + roster 등록 대조 + kicker** (5) **첫 카드 생성·발령** (6) 개시 선언(발령 결과 포함). 임명장에 이 6단계 전부를 쓰고, "스킬 표준 절차가 이 목록보다 넓으면 표준을 따른다"는 문장을 함께 넣는다.

**살아남은 것 — 체크포인트 커밋 규칙이 하루치를 살렸다**
```
판 conductor-core-contract-1   체크포인트 커밋 6개
판 mailbox-relay-1             체크포인트 커밋 6개
워크트리 21개 (미커밋 11곳 포함)  전부 디스크에 그대로
```
**앱과 판이 다 죽었는데 잃은 것은 실행 중 프로세스와 대화 맥락뿐이었다.** "프로세스가 원장이 아니다. 기록은 디스크에 남긴다"가 실제로 값을 한 날이다.

**처방(적용)**: 발령 관문에 **메모리 관문(2b)** 신설 — 스왑 여유 4GB 미만이면 신규 발령 정지, 2GB 미만이면 판 전체 정지 후 kyle 보고. 발령 보고에 부하와 스왑 여유를 함께 적는다. **가동 7일 초과 + 스왑 여유 절반 미만이면 kyle에게 재부팅 권고.**

**재부팅 후 실측**: 스왑 0.00MB, 프로세스 915개, 압축 2.4GB. 다만 macOS가 재색인·캐시정리·자산받기를 하며 부하 66~82를 만들었다 — **재부팅 직후는 판을 깔 시점이 아니다.** 색인 계열 CPU가 내려간 뒤 시작한다.
