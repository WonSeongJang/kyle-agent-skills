# Migration Checklist (Legacy -> MoR)

## Gate 0: 사전 동결

- [ ] 결제 관련 배포 윈도우를 확정했다.
- [ ] 결제 도메인 파일 소유권(담당자/리뷰어)을 확정했다.
- [ ] 롤백 조건을 수치로 정의했다(예: 결제 성공률, 웹훅 실패율).

## Gate 1: 베이스라인 수집

- [ ] `scripts/find_payment_touchpoints.sh` 결과를 저장했다.
- [ ] 현재 결제 상태 전이 다이어그램을 작성했다.
- [ ] 지급/원장 반영 지점을 식별했다.

## Gate 2: 어댑터 삽입

- [ ] 공급자별 분기를 어댑터 계층으로 이동했다.
- [ ] 내부 표준 상태 모델을 도입했다.
- [ ] 기존 API 응답 계약을 깨지 않도록 호환 레이어를 유지했다.

## Gate 3: 웹훅 보강

- [ ] raw body 기반 서명 검증을 구현했다. `[POLAR_WEBHOOK_SIGNATURE]`, `[LEMON_WEBHOOK_SIGNING]`
- [ ] 이벤트 멱등 키를 도입했다(`provider + event_id`).
- [ ] 중복 웹훅 재수신 테스트를 통과했다.

## Gate 4: 데이터 정합성 검증

- [ ] 전환 전/후 주문 건수와 상태 분포를 비교했다.
- [ ] 지급된 크레딧/권한 총합이 일치하는지 검증했다.
- [ ] 실패/환불 처리 시 원장 역분개가 정상인지 확인했다.

## Gate 5: 컷오버

- [ ] 단계적 활성화 플래그를 적용했다.
- [ ] 관측 지표 대시보드를 켰다.
- [ ] 온콜 대응 문구/플레이북을 공유했다.

## Gate 6: 롤백 가능성 유지

- [ ] 플래그 기반 즉시 롤백 경로를 리허설했다.
- [ ] 롤백 후에도 멱등성으로 이중 지급이 발생하지 않음을 검증했다.
- [ ] 장애 공지 템플릿과 복구 절차를 최신화했다.
