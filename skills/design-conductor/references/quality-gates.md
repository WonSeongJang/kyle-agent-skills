# 디자인 품질 기준

## 모든 작업

- 사용자, 불편, 더 쉽게 만들 일을 한 문장으로 설명한다.
- 주 제작자 하나를 명시한다.
- 기존 토큰과 컴포넌트를 재사용했는지 확인한다.
- 선택하지 않은 주요 후보와 제외 이유를 한 줄로 남긴다.
- 실패한 검사와 확인하지 못한 부분을 숨기지 않는다.

## 웹 UI

### 코드

- 의미 있는 HTML과 키보드 조작을 확인한다.
- 포커스 표시, 폼 라벨, 오류 문구, 빈 상태를 확인한다.
- `prefers-reduced-motion`과 애니메이션 필요성을 확인한다.
- 이미지 크기, 대체 텍스트, 로딩 방식을 확인한다.
- 임의의 색과 간격보다 프로젝트 토큰을 우선한다.

### 실제 화면

- 데스크톱과 모바일을 각각 연다.
- 가로 넘침, 잘림, 겹침, 고정 헤더, 모달을 확인한다.
- 주요 버튼을 실제로 누른다.
- 로딩, 오류, 빈 상태, 긴 텍스트를 가능한 범위에서 확인한다.
- 완료 보고에 확인한 URL, 화면 크기, 스크린샷 또는 관찰 결과를 남긴다.

## Figma 구현

- 정확한 node ID의 디자인 문맥과 스크린샷을 함께 확인한다.
- 에셋과 변수를 프로젝트 방식으로 옮긴다.
- Figma 스크린샷과 실제 화면을 같은 크기에서 비교한다.
- Figma 연결이나 원본이 없으면 1:1 일치를 주장하지 않는다.

## 슬라이드

- 모든 슬라이드의 제목, 본문 넘침, 이미지 비율을 확인한다.
- 발표 화면과 내보낸 PDF 또는 PNG를 각각 연다.
- PPTX 또는 Figma 변환은 실험적 출력으로 취급하고 직접 확인한다.
- 원격 이미지 대신 납품물에 포함되는 로컬 에셋을 우선한다.

## 이미지

- 화면비, 텍스트 정확성, 주 피사체, 브랜드 색을 확인한다.
- 참고 이미지를 썼다면 유지해야 할 요소와 바꿀 요소를 구분한다.
- 사용자가 특정 모델을 지정하지 않으면 Codex 내장 이미지 생성을 기본값으로 사용한다.

## 다이어그램과 시각 문서

- 읽는 방향이 한눈에 보이는지 확인한다.
- 글자 겹침, 잘림, 너무 작은 글자를 확인한다.
- 장식보다 관계와 주장 전달을 우선한다.
- 원본 Markdown 또는 Excalidraw 파일을 수정 가능한 기준 파일로 남긴다.

## 모드별 완료 증거

| 모드 | 최소 증거 |
|---|---|
| QUICK | 결과물 직접 확인 1회 |
| STANDARD | 코드 검사 + 데스크톱과 모바일 실제 화면 |
| STRICT | 원본 비교 + 주요 상태 + 접근성 + 변경 전후 스크린샷 |
